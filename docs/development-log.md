# PRIME LAB 開発変更履歴

コードを変更した場合は、変更の理由・内容・検証方法・結果を追記する。研究仮説の実験結果（data/runs）とは分けて記録する。

## 2026-10-21：実行ごとにランダムな着想キーワードを選択

### 変更理由
同日に研究を再実行しても、日付固定の乱数種により同じ3語（例：窓・遠近法・圧縮）が選ばれ、仮説が似通いやすかった。また、初等的に自明な剰余類の仮説が多数生成された。

### 変更内容
- `src/prime_lab/inspiration.py`：従来の再現可能な日付ベースの `pick(day)` は残し、新規に `pick_random(count=3)` を追加。SystemRandomで異なる3分野から単語を抽出する。
- `src/prime_lab/ai_daily.py`：AI研究実行時に `pick_random()` を使用し、実行ごとに着想を更新。使用語は各研究記録の `inspiration` に保存する。
- `src/prime_lab/ai_batch.py`：既知・自明な剰余類や数値上限だけを変えた案を避けるよう、AIへの指示を強化。

### 検証状況
GitHubのmainブランチへの3ファイルのコミットは成功。変更後のGitHub Actionsの再実行およびテスト結果は、この記録時点では未確認。自明な仮説の機械的除外・学術的新規性の照合は未実装。ランダム抽出では同じ組み合わせの再登場はあり得る。

### 今後の変更記録ルール
1. 変更目的・問題の根拠
2. 変更ファイル・具体的な動作差分
3. テスト方法・実行結果（未実行なら未実行と明記）
4. 残る制約と次の改善候補

## 2026-10-21：剰余に偏らない研究対象の追加

### 変更理由
従来の3種類はすべて余りを中心とするため、生成候補が既知・自明な剰余の性質に集中した。

### 変更内容
- `structured.py`：従来の剰余3種類を維持し、`prime_gap_bound`（隣接素数間隔の上限）と`prime_count_window`（移動区間の素数個数下限）を追加。有限範囲の反例を返す。入力は宣言的なJSONのみ。
- `llm_structured.py`：新形式 `kind,limit,window,threshold,motivation` を受理。
- `ai_batch.py`：Geminiに新2種類を合計6件以上含めるよう依頼。
- `tests/test_expanded_hypotheses.py`：新2種類の反例・パーサー・範囲検証のテストを追加。

### 検証状況・限界
GitHubへのコミット完了。GitHub Actionsでのテスト成功と実際のGemini生成結果は未確認。生成するのは有限範囲の条件検証であり、数学的な新規性の審査や非自明性の自動判定は未実装。AIが新種類を6件以上生成する保証もない。今後、審査エンジンとさらに多様な数学的関係を実装する必要がある。
